# 共享筆記：讓同事能編輯、但看不到私人內容

日期：2026-10-13　狀態：設計已口頭同意，待審閱文件

## 目標

- 擁有者可以把**個別筆記**標成「共享」，同事能看、能編輯、能新增共享筆記。
- 同事**完全看不到**擁有者的私人筆記、日記、追蹤記錄，以及它們的 git 歷史。
- 公開（訪客可見）仍然**只有擁有者**能設定。
- 一個網站、一份程式，依登入的 token 自動判斷身分。

## 不做的事

- 不自動搬移現有筆記：擁有者在編輯器逐篇改成「共享」。
- 同事沒有追蹤功能，也不能把筆記設為公開。
- 不加密，也不做檔案層級的權限控管：隱私完全靠「放在不同的 repo」。

## 為什麼要拆 repo

GitHub 的權限以整個 repo 為單位。能編輯 `notebook-data` 的人，看得到裡面所有檔案和完整歷史。網站上的「私人」只代表「不同步到公開分支」，擋不住有 repo 權限的人。所以共享內容必須放在另一個 repo，同事只會被加進那個 repo。

## 資料位置

| 位置 | 誰能存取 | 內容 |
|---|---|---|
| `coconutbee/notebook-data` | 只有擁有者 | 個人筆記（含日記）、`metrics/`、個人筆記的圖片、`config.json`（個人分類） |
| `<組織>/notebook-shared` | 擁有者＋同事 | 共享筆記、共享筆記的圖片、`config.json`（共享分類） |
| `coconutbee/notebook` 的 `public-notes` 分支 | 所有人可讀；只有擁有者寫入 | 公開筆記副本 |

- 兩個資料 repo 的檔案格式完全相同（`notes/<分類>/[日期-]標題.md`、`images/<年-月>/…`、`config.json`）。
- `<組織>` 由擁有者建立組織時決定，寫入 `src/config.ts` 的 `SHARED_OWNER`。
- repo 名稱 `notebook-shared` 寫入 `SHARED_REPO`。

## Token 與身分

fine-grained token 只能屬於一個擁有者（個人帳號或組織），所以：

- **擁有者**輸入兩把 token：
  - 個人 token：`notebook-data`＋`notebook`，Contents 讀寫。
  - 共享 token：組織的 `notebook-shared`，Contents 讀寫。共享 token 可以留空，留空就只有個人區。
- **同事**只輸入共享 token。
- 兩把 token 都存在 localStorage（`notebook.token`、`notebook.sharedToken`），登出時一併清除。

身分判斷（設定畫面儲存時檢查一次，之後每次載入沿用）：

| 讀得到 `notebook-data` | 讀得到 `notebook-shared` | 身分 |
|---|---|---|
| 是 | 是／否 | `owner` |
| 否 | 是 | `coworker` |
| 否 | 否 | 顯示錯誤，不登入 |
| 沒有 token | — | `visitor`（現有行為） |

## 程式架構

**Note 的識別**
- `Note` 加上 `space: 'personal' | 'shared'`。
- 兩邊可能有相同路徑，所以 App 內的識別與路由改用 `id`：
  - 個人筆記：`id` 就是 `path`（現有網址不變）。
  - 共享筆記：`id` 是 `shared/` 加上 `path`。

**store**
- `github` 變成 `{ data?, shared?, pub? }`。
- `mode` 變成 `'owner' | 'coworker' | 'visitor'`。
- 載入時對每個讀得到的 space 各自做現有的流程：列出檔案、讀 `config.json`、讀筆記、讀圖片清單。追蹤資料只從 personal 讀。
- 讀寫一律依 `note.space` 選對應的 GitHub 物件；衝突規則不變（帶 sha、409／422 不覆蓋）。
- 分類：
  - `config` 與 `subcategoriesOf` 依 space 分開。
  - 列表與側欄顯示兩邊分類的聯集。
  - 編輯器依「存放位置」列出該 space 的分類。

**搬移（個人 ↔ 共享）**
1. 把筆記用到的圖片逐一複製到目標 repo；目標已有同 sha 的檔就跳過。
2. 不帶 sha 在目標建立筆記；已有同路徑檔會得到 422，就停下並提示，不覆蓋。
3. 刪除原 repo 的檔案；sha 不符就保留原檔並提示，同現有的「移動筆記」。
4. 原 repo 的圖片不刪。之後擁有者可在個人區的「清理未使用的圖片」自行處理。

切換前要跳確認：
- **個人 → 共享：** 「只會把目前內容帶過去，個人 repo 的舊版本不會外流。」
- **共享 → 個人：** 「共享 repo 的 git 歷史仍保有舊版本，同事看得到以前的內容。」

**公開同步**
- 只在擁有者的瀏覽器執行，範圍是兩個 space 裡所有 `visibility: public` 的筆記。
- 公開分支的路徑：
  - 個人筆記：維持 `notes/…`、`images/…`。
  - 共享筆記：`shared/notes/…`、`shared/images/…`。這樣筆記裡的 `../../images/…` 相對路徑仍然正確。
- `index.json` 每筆加上 `space`，訪客模式依它還原 `id` 與圖片網址。
- 同事改了已公開的共享筆記時，公開版本會暫時是舊的。擁有者每次載入完成後，自動執行一次 `syncPublic`；它只比對 sha，沒變就不寫入。

**介面**

| | 擁有者 | 同事 |
|---|---|---|
| 筆記列表、搜尋、標籤分布 | 兩邊合併，卡片顯示「個人／共享」徽章 | 只有共享 |
| 卡片「移到」選單 | 只列出同一 space 的分類 | 同左 |
| 編輯器 | 多「存放位置：個人／共享」，以及現有的公開設定 | 沒有存放位置與公開設定 |
| 首頁 | 現有內容 | 最近編輯的共享筆記＋分類 |
| 追蹤分頁 | 有 | 沒有（導覽列與路由都移除） |
| 設定 | 個人分類、共享分類、兩把 token、登出 | 共享分類、登出 |

## 錯誤處理

- 共享 token 失效（401）或沒有權限（403／404）時，擁有者照常使用個人區，並顯示提示「共享區無法載入：…」。同事則顯示錯誤並回到設定畫面。
- 搬移中途失敗時，訊息要說明停在哪一步，並保證不覆蓋、不遺失：最壞情況是兩邊各有一份。

## 擁有者要在 GitHub 上做的事（實作時附逐步說明）

1. 建立免費組織，並在組織設定允許 fine-grained token。
2. 在組織底下建立私人 repo `notebook-shared`。
3. 邀請同事加入組織，給這個 repo 的寫入權限。
4. 擁有者和同事各自建立共享 token。

## 測試

使用現有的 `src/test/fakeGitHub.ts`（已支援多個 repo）：

- 依可存取的 repo 判斷 `owner`／`coworker`／錯誤。
- 個人 → 共享的搬移：圖片一起複製、原檔刪除；目標同名時是 422，不覆蓋且原檔保留。
- 公開同步：共享的公開筆記出現在 `shared/notes/…`，私人筆記不出現；同事身分不會呼叫公開分支。
- 兩邊相同路徑的筆記可以共存，`id` 不衝突。
